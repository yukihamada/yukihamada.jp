監査ゲート A–G

AIで作る速さは百倍になった。鍵のかけ忘れも、百倍になる。
サービスを世界に出す前に、自分のドアを一度だけ叩く7項目です。

自分の公開MCPサーバー7本をAIに監査させたら、3本が無認証で書き込める状態でした。鍵は設計してあったのに、配線されていなかった。同じ穴を、あなたが踏まないように。

使ったチェックリストを、そのまま置いておきます。→ 経緯は紙芝居で
A

認証ゲート（Authentication）

書き込み・破壊系の操作に必ず認証を要求する。「認証を設計した」と「全経路に配線した」は別物。トークン未設定なら開くのではなく閉じる（fail-closed）。

無認証で書き込みAPIを叩いて、拒否されることを実際に確認した
B

秘密の非露出（Secrets）

パスワード・APIキー・トークンをコード・ログ・エラー本文・クライアントに出さない。秘密はサーバー側だけが持ち、渡す権限は最小の一つだけ。

レスポンスとログに鍵・内部パスが漏れていないか grep した
C

トランスポート（Transport）

HTTPS強制。プロトコルバージョンのエコー、メソッドの出し分け（GET/POST/OPTIONS）を仕様どおりに。中間者・ダウングレードを許さない。

httpでアクセスしてhttpsに昇格されることを確認した
D

入力検証（Input validation）

SQLはパラメータ化（文字列連結しない）。URL・ファイル名・IDの形式を検証。外部から渡るURLはSSRF対策（解決後IPがprivate/loopback/内部なら拒否、DNSリバインド・リダイレクトも塞ぐ）。

169.254.169.254・localhost・..%2f を投げて弾かれることを確認した
E

CORS / オリジン

ワイルドカード * を惰性で付けない。書き込みは Origin / CSRF を検証。クロスオリジンで意図しない呼び出しが通らないように。

別オリジンからの書き込みが拒否されることを確認した
F

濫用対策（Abuse / rate limit）

IPあたり・グローバルの日次上限。課金につながる処理（生成・送信）はキャッシュと上限で守る。匿名枠は信頼できるIPヘッダ（例: fly-client-ip）でキー化。

上限を超えたら429が返ることを確認した
G

過剰開示（Over-exposure）

必要な情報だけ返す。内部ID・スタックトレース・他人のデータ・下書き・非公開リストを露出しない。公開既定ではなく非公開既定（fail-closed）に。

一覧・詳細APIに他人の非公開データが混ざっていないか確認した

泥棒テスト

公開する前に、一度、泥棒になる。鍵を持たずに自分のドアを開けてみて、拒否されたら合格。すんなり開いたら、それは世界中に開いています。

# 1. 鍵なしで書き込みAPIを叩く → 401/403 が返れば A 合格
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://your.app/api/write
→ 401  # 拒否された＝合格

# 2. 内部メタデータへのSSRFを試す → 弾かれれば D 合格
curl -s -X POST https://your.app/api/fetch -d '{"url":"http://169.254.169.254/"}'
→ "内部ホストは指定できません"

# 3. 別オリジンからの書き込み → CSRF で弾かれれば E 合格
curl -s -X POST https://your.app/api/write -H "Origin: https://evil.example"
→ ここで通ったら、世界中に開いています
原則は、三つだけ。

迷ったら、閉じる（fail-closed）。秘密は、書かない（最小の鍵を一つ）。公開前に、泥棒として叩く。
鍵は、かけたつもりじゃなく、かけて、確かめてから。
